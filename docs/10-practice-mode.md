# 10. 練習ビュー（ギター耳コピ用）

曲のピッチ（キー）と速度を独立して変えながら、曲の細かい位置から繰り返し聴ける「練習ビュー」を追加する。ステップ 1〜5（[09](./09-remaining-diffs.md) まで）で現行版と同等になったあとの、新機能。

状態: **要件確定・音質検証（スパイク）待ち**

## 目的と使い方

- 使う人: ギタリスト。耳コピのために、曲のキーや速度を変えて練習する。
- 主な環境: iOS Safari のホーム画面アプリ（**iOS 16.4 以降**）。PC ブラウザ・Android の Chrome でも動く技術を選ぶ。
- 使い方: メインビューで曲を再生 → ヘッダーのボタンで練習ビューへ → 波形をタップして頭出しし、ピッチ・速度を調整しながら聴く。

## 要件

### 画面の切り替え

- ルート `/practice` を追加する。
- ヘッダーの「?」（デバッグ）ボタンの隣に、練習ビューのボタンを置く。
- 練習ビューのボタンとデバッグのボタンは、どちらも押すたびに **メインビューとトグル**する。
    - メインビュー以外（練習・デバッグ）から同じボタンを押すと、**直前に開いていたメインビュー**（`home` / `folder` / `search`。フォルダや検索語を含む）へ戻る。
    - 練習ビューからデバッグを押す場合は、デバッグへ移る。そこからデバッグをもう一度押すと、メインビューへ戻る（練習ビューには戻らない）。
- 練習ビューは、メインで再生中の曲を引き継いで開く。
    - 入場時に、メインの再生は一時停止する。メインへ戻っても自動では再開しない。
    - 曲を替えるときは、メインビューで選び直す（練習ビュー内に曲の切り替えはない）。
    - 曲がない状態（再読み込み直後など）で開いたときは、「メインビューで曲を再生してから開いてください」と表示する。

### 練習ビューの構成（縦向き）

上から順に次の構成にする。縦向きの画面に、10 段のシークバーが収まる高さにする。

1. **シークバー（10 段）**
2. **再生 / 一時停止ボタン**
3. **ピッチ変更ボタン**
4. **速度変更ボタン**

#### シークバー

- 曲の長さに関わらず **10 段固定**。曲を 10 等分し、各段が全体の 1/10 を表す（3 分の曲なら 1 段 18 秒）。ズームや段数の切り替えはない。
- 各段に **波形**を重ねて表示する。
- 現在の再生位置を示す線と、各段の開始時刻のラベルを出す。
- 操作:
    - タップ: その位置へ移動する。再生中なら続けて再生し、停止中は位置だけを設定する。
    - ドラッグ: 音は鳴らさず、指を離した位置から再開する（再生中だった場合）。

#### ピッチ変更（半音単位）

- ボタンを押すとダイアログが開く。
- ダイアログの中身: プラス、マイナス、原曲に戻すリセットの 3 つのボタンと、現在のキー表示（`+2`、`-3`、`0`）。
- 範囲は ±12 半音。セント単位の微調整はない。
- ピッチを変えても、速度は変わらない。

#### 速度変更

- ボタンを押すとダイアログ（またはパネル）が開く。
- スライダー: 0.25〜2 倍、0.05 刻み。現在値は `×0.75` のように表示する。
- 即設定ボタン: 0.25 / 0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 倍。
- 速度を変えても、音程は変わらない。

### 再生の動作

- 曲の終わりで停止し、先頭に戻る。次の曲へは進まない。
- 設定（ピッチ・速度・位置）は保存しない。練習ビューを開くたびに、ピッチ 0・速度 1 倍・先頭から始まる。
- PC では Space キーで再生 / 一時停止を切り替える。
- 曲の長さの上限は 15 分。超える場合は「長すぎて読み込めません」と表示する（判定方法は、メインの `player.duration` が使えるのでそれを使う。使えなければデコード前のファイルサイズで判断する）。

### 対象外

区間ループ（A-B）、マーカー、ズーム・段数の切り替え、セント単位の微調整、曲ごとの設定の保存、ロック画面（Media Session）での操作、画面ロック中の再生、横向き対応、練習ビュー内での曲の切り替え。

## 技術方針

### 全体

- ブラウザ標準の **Web Audio API と AudioWorklet** を使う。OpenAL はブラウザでは使えず、ピッチ変更も速度と連動するだけなので採用しない。
- 曲全体をデコードして（`decodeAudioData`）、デコード済みの音声データから再生・波形の作成をする。波形が必要なため、全曲デコードが前提になる。シークの位置もサンプル単位で決まる。
- 「速度だけ」「ピッチだけ」を独立に変えるため、タイムストレッチとピッチシフトのライブラリを使う（下の「候補」）。
- 曲のデータは、Drive の `downloadFile`（進捗つき）で取得する。メインの再生で取得済みのデータの共有は、しない（ビューを独立させるため）。
- 既存の `features/player` は変更しない。練習ビューは `features/practice` として独立させる。

### 候補（スパイクで比較して決める）

| 案 | 内容 | 想定 |
| --- | --- | --- |
| A（比較の基準） | `<audio>` の `playbackRate` と `preservesPitch` | 速度変更だけ。ピッチだけを変える手段がないので、本採用はしない |
| B | AudioWorklet と SoundTouch 系（[@soundtouchjs/audio-worklet](https://www.npmjs.com/package/@soundtouchjs/audio-worklet) など） | 軽くてスマホ向き。和音の多い曲で音がやや濁る可能性がある。ライセンスは LGPL |
| C | AudioWorklet と Rubber Band の WASM 版（[rubberband-wasm](https://github.com/Daninet/rubberband-wasm) など） | 音質が最良の見込み。CPU 負荷が高い。ライセンスは GPL（商用は別ライセンス）。公開 URL で配信する場合の扱いを、採用前に確認する |

各パッケージの API・ライセンス・iOS での動作は、スパイクの中で確認する（この時点では未確認）。

### iOS Safari（16.4 以降）の注意点

- **マナーモード**: Web Audio は、マナーモードだと鳴らないことがある。`navigator.audioSession.type = "playback"` を設定して、マナーモードでも鳴るようにする。iOS 16.4 未満は対象外（無音の `<audio>` を使う古い回避策は入れない）。
- **音声の開始**: `AudioContext` の開始（resume）は、ユーザーの操作（再生ボタン）の中で行う。
- **中断からの復帰**: 電話やアプリの切り替えで `AudioContext` が止まる（`interrupted` / `suspended`）ことがある。画面へ戻ったときに再開できるようにする。
- **メモリ**: デコード後の音声は、4 分のステレオで約 85MB、15 分で約 300MB になる。上限（15 分）は、実機で問題が出たら下げる。

### 波形

- デコード後に、各段 × 画面の幅（px）ごとの最小値・最大値を 1 度だけ集計し、canvas に描く。ステレオは左右を混ぜて（平均して）描く。
- 画面の幅が変わったとき（回転・リサイズ）は、再集計する。

## 構成案（スパイクのあとに確定）

```
src/features/practice/
├─ PracticePage.vue        練習ビューの画面（シークバー、コントロール）
├─ practice-store.ts       Pinia: 読み込み状態、再生位置、ピッチ、速度、再生 / 停止
├─ engine/                 Web Audio の再生エンジン（スパイクで決めた方式）
├─ waveform.ts             波形のピーク集計（純粋関数）
├─ seek-layout.ts          時刻 ⇄ 段・位置の変換（純粋関数）
├─ PitchDialog.vue / SpeedDialog.vue
└─ index.ts
```

- 練習ビューへの曲の引き継ぎは、`usePlayerStore().current` を LibraryPage 側の配線（または app 層）から渡す。practice は player を直接 import しない。
- ルート `practice` を `router.ts` に追加する。メインビュー（`home` / `folder` / `search`）への戻り先は、`router.afterEach` で記録する（app 層）。
- ヘッダー（`AppHeader.vue`）の 2 つのボタンは、上の「画面の切り替え」の規則で動く（トグルの判定は純粋関数に切り出す）。
