# 10. 練習ビュー（ギター耳コピ用）

曲のピッチ（キー）と速度を独立して変えながら、曲の細かい位置から繰り返し聴ける「練習ビュー」を追加する。ステップ 1〜5（[09](./09-remaining-diffs.md) まで）で現行版と同等になったあとの、新機能。

状態: **方式決定済み（SoundTouch + Worker + AudioWorklet）・本実装済み・実機確認待ち**

## 目的と使い方

- 使う人: ギタリスト。耳コピのために、曲のキーや速度を変えて練習する。
- 主な環境: iOS Safari のホーム画面アプリ（**iOS 16.4 以降**）。PC ブラウザ・Android の Chrome でも動く技術を選ぶ。
- 使い方: メインビューで曲を再生 → ヘッダーのボタンで練習ビューへ → 波形をタップして頭出しし、ピッチ・速度を調整しながら聴く。

## 要件

### 画面の切り替え

- ルート `/practice` を追加する。
- ヘッダーのアイコンボタンで、画面を切り替える（トグルではなく、押した画面へ移る）。左から順に:
    - `queue_music`（リスト）: メインのリストビューを開く。**直前に開いていたメインビュー**（`home` / `folder` / `search`。フォルダや検索語を含む）に戻る。
    - `ear_sound`（耳コピ）: 練習ビューを開く。
    - `settings`（設定・デバッグ情報）: デバッグ画面（`/debug`）を開く。従来の「?」ボタンの置き換え。
    - 「サインアウト」ボタンはヘッダーから外し、デバッグ画面（認証のセクション）に移した（使う機会が少ないため）。
- 今開いている画面のボタンは、うすい丸で強調する。同じボタンをもう一度押しても何も変わらない。
- アイコンは Material Symbols の名前で決めた。アプリが使っているのは従来の Material Icons フォントで、`ear_sound` がないため、近い `hearing`（耳）で代用する（`queue_music`・`settings` は同名がある）。
- 練習ビューは、メインで再生中の曲を引き継いで開く。
    - 入場時に、メインの再生は一時停止する。メインへ戻っても自動では再開しない。
    - 曲を替えるときは、メインビューで選び直す（練習ビュー内に曲の切り替えはない）。
    - 曲がない状態（再読み込み直後など）で開いたときは、「メインビューで曲を再生してから開いてください」と表示する。

### 練習ビューの構成（縦向き）

上から順に次の構成にする。縦向きの画面に、10 段のシークバーが収まる高さにする。

1. **シークバー（10 段）**
2. **コントロールエリア（2 カラム）**

| | 左カラム | 右カラム |
| --- | --- | --- |
| 上 | 時間表示（現在位置 / 曲の長さ） | ピッチ（1 行） |
| 下 | 戻る・再生 / 一時停止・進むの 3 ボタン（丸、各 48px。横一列） | 速度（1 行） |

- ピッチ・速度は、ダイアログを使わず、画面に直接置く。それぞれ横一列で、「ラベル: 現在値　［−］［元の値］［＋］」の並びにする（例: `ピッチ: +2　［−］［0］［＋］`、`速度: ×0.75　［−］［×1］［＋］`）。
- 真ん中のボタンには元の値（ピッチは `0`、速度は `×1`）を出し、押すとその値に戻すリセットになる。
- 幅の狭い画面（iPhone の縦向き）でも、2 カラムが 1 行ずつに収まるようにする。

#### シークバー

- 曲の長さに関わらず **10 段固定**。曲を 10 等分し、各段が全体の 1/10 を表す（3 分の曲なら 1 段 18 秒）。ズームや段数の切り替えはない。
- 各段に **波形**を重ねて表示する。
- 現在の再生位置を示す線と、各段の開始時刻のラベルを出す。
- **マーカー**: 最後にタップした位置に、再生位置の線と同じ形の線（色は青）を置く。タップするたびに、古いマーカーは消えて新しい位置に置き直す。開いた直後はマーカーなし。ドラッグ・戻るボタンではマーカーは動かない。
- 操作:
    - タップ: その位置へ移動して、マーカーを置く。再生中なら続けて再生し、停止中は位置だけを設定する。
    - ドラッグ: 音は鳴らさず、指を離した位置から再開する（再生中だった場合）。マーカーは置かない。

#### 戻るボタン・進むボタン

再生ボタンの左右に置く（戻る・再生・進むの順）。戻るボタンを押したときの動き（位置は、再生中でも停止中でも同じ規則）:

- マーカーがあり、再生位置がマーカーから **1 秒を超えて**後ろにある: マーカーの位置へ戻る。
- それ以外（マーカーがない、マーカーの前、マーカーから 1 秒以内）: 曲の先頭へ戻る。

進むボタンは、再生位置が**マーカーより前**にあるときだけ、マーカーの位置へ進む。マーカーがない、または再生位置がマーカー以降のときは、何も起きない。

どちらも、再生中なら続けて再生し、停止中は位置だけを移す。

#### ピッチ変更（半音単位）

- 右カラム上部に置く。「ピッチ: 現在のキー［−］［0］［＋］」の 1 行。現在のキーは `+2`、`-3`、`0` の形で表示する。
- − / ＋ で 1 半音ずつ変える。真ん中の `0` ボタンで 0（原曲）に戻す。
- 範囲は ±12 半音。端では、それ以上動かせない。セント単位の微調整はない。
- ピッチを変えても、速度は変わらない。

#### 速度変更

- 右カラム下部に置く。「速度: 現在の速度［−］［×1］［＋］」の 1 行。現在値は `×0.75` のように表示する。
- − / ＋ で 0.25 倍ずつ変える。真ん中の `×1` ボタンで 1 倍に戻す。
- 範囲は 0.25〜2 倍。端では、それ以上動かせない。スライダーと即設定ボタンはない。
- 速度を変えても、音程は変わらない。

### 再生の動作

- 曲の終わりで停止し、先頭に戻る。次の曲へは進まない。
- 設定（ピッチ・速度・位置）は保存しない。練習ビューを開くたびに、ピッチ 0・速度 1 倍・先頭から始まる。
- PC では Space キーで再生 / 一時停止を切り替える。
- 曲の長さの上限は 15 分。超える場合は「長すぎて読み込めません」と表示する（判定方法は、メインの `player.duration` が使えるのでそれを使う。使えなければデコード前のファイルサイズで判断する）。

### 対象外

区間ループ（A-B）、複数のマーカーや名前つきマーカー、ズーム・段数の切り替え、セント単位の微調整、曲ごとの設定の保存、ロック画面（Media Session）での操作、画面ロック中の再生、横向き対応、練習ビュー内での曲の切り替え。

## 技術方針

### 全体

- ブラウザ標準の **Web Audio API と AudioWorklet** を使う。OpenAL はブラウザでは使えず、ピッチ変更も速度と連動するだけなので採用しない。
- 曲全体をデコードして（`decodeAudioData`）、デコード済みの音声データから再生・波形の作成をする。波形が必要なため、全曲デコードが前提になる。シークの位置もサンプル単位で決まる。
- 「速度だけ」「ピッチだけ」を独立に変えるため、タイムストレッチとピッチシフトのライブラリを使う（下の「候補」）。
- 曲のデータは、Drive の `downloadFile`（進捗つき）で取得する。メインの再生で取得済みのデータの共有は、しない（ビューを独立させるため）。
- 既存の `features/player` は変更しない。練習ビューは `features/practice` として独立させる。

### 処理系の方式（決定）

**SoundTouch（[@soundtouchjs/core](https://www.npmjs.com/package/@soundtouchjs/core)、MPL-2.0）を、Web Worker で計算し、AudioWorklet で再生する。**

- SoundTouch は「ピッチだけ」を変える作り（レート変換 = ピッチ倍率、時間伸縮 = 1 ÷ ピッチ倍率）。時間伸縮の `tempo` を「速度 ÷ ピッチ倍率」に上書きして、速度とピッチを独立に変える。時間伸縮の調整値（区切りの長さ・探索範囲・重ね幅・速い探索）は既定のまま。
- 計算（SoundTouch）は Worker が約 46 ms 分（2048 フレーム）ずつ先回りして作り、AudioWorklet はできた音を順に流すだけにする。AudioWorklet 側に約 190 ms（8192 フレーム）の作り置きがあるので、計算が一時的に遅れても音が途切れない。
- ピッチ・速度を変えてから音に反映されるまで、最大で作り置き分（約 0.2 秒）の遅れがある。耳コピの用途では問題ない。
- ライセンス: MPL-2.0（ファイル単位のコピーレフト）。`@soundtouchjs/core` を改変せずに、依存として使う。
- AudioWorklet と Worker はメッセージ（`MessagePort`）でつなぐ。`SharedArrayBuffer` は、cross-origin isolation（COOP/COEP）が要って Google 認証のポップアップと相性が悪いので使わない。

#### スパイクの結果

| 案 | 結果 |
| --- | --- |
| A: `<audio>` の `playbackRate` | 速度だけ変えられる。ピッチだけを変えられないので不採用 |
| Rubber Band（WASM、GPL） | 速度・ピッチを変えるたびに 10 秒以上の解析が必要で、ライセンスも重いので不採用 |
| SoundTouch（AudioWorklet 内で計算） | 音質は申し分なし。MacBook Pro 2019 の Chrome だけ、計算の負荷の波（最大 20 ms 程度。1 回の予算は約 2.9 ms）で音が途切れた（Safari・iPhone 15 の Safari は問題なし） |
| **SoundTouch（Worker で計算 + AudioWorklet で再生）** | **MacBook の Chrome でも途切れず、iOS の同等アプリに遜色ない音質（採用）** |

### iOS Safari（16.4 以降）の注意点

- **マナーモード**: Web Audio は、マナーモードだと鳴らないことがある。`navigator.audioSession.type = "playback"` を設定して、マナーモードでも鳴るようにする。iOS 16.4 未満は対象外（無音の `<audio>` を使う古い回避策は入れない）。
- **音声の開始**: `AudioContext` の開始（resume）は、ユーザーの操作（再生ボタン）の中で行う。
- **中断からの復帰**: 電話やアプリの切り替えで `AudioContext` が止まる（`interrupted` / `suspended`）ことがある。画面へ戻ったときに再開できるようにする。
- **メモリ**: デコード後の音声は、4 分のステレオで約 85MB、15 分で約 300MB になる。上限（15 分）は、実機で問題が出たら下げる。

### 波形

- デコード後に、曲を 1 回なぞって、各段を 2400 個に区切った最小値・最大値を集計する（曲のデータは Worker へ渡すと使えなくなるので、この時点で行う）。ステレオは左右を平均して（モノラルにして）集計する。
- 画面へは、この集計結果を画面の幅（実ピクセル）の列数に作り直して、canvas に描く。幅が変わったとき（回転・リサイズ）も、集計結果から作り直すだけで済む。

```
├─ StepControl.vue         横一列の「ラベル: 現在値 ［−］［元の値］［＋］」（ピッチ・速度で共通）
├─ practice-store.ts       Pinia: 読み込み、再生位置、マーカー、ピッチ、速度、再生 / 停止、戻る、ドラッグ

├─ waveform.ts             波形の集計（純粋関数）
├─ params.ts               ピッチ・速度の範囲と表示（純粋関数）
├─ engine/
│  ├─ engine.ts            AudioContext・Worker・AudioWorklet をまとめた再生エンジン（store はインターフェースだけに頼る）
│  ├─ soundtouch-worker.ts SoundTouch の計算（Worker）
│  ├─ soundtouch-processor.ts 再生だけ（AudioWorklet）
│  └─ messages.ts          3 者の間のメッセージの型
└─ index.ts
src/app/
├─ PracticeRoute.vue       メインで再生中の曲を引き継ぎ、メインの再生を止めて PracticePage へ渡す
└─ header-nav.ts           ヘッダーのボタンの行き先を決める（純粋関数）
src/shared/ui/
└─ usePlayPauseKey.ts      Space キーで再生 / 停止（player から移動）
```

- 練習ビューへの曲の引き継ぎは、app 層の `PracticeRoute.vue` が `usePlayerStore().current` を props で渡す。practice は player を直接 import しない。
- ルート `practice` は、Worker と SoundTouch を開いたときに読み込むよう、遅延読み込みにしている。
- メインビュー（`home` / `folder` / `search`）への戻り先は、`AppHeader.vue` が現在のルートを監視して記録する（`fullPath`。フォルダや検索語を含む）。行き先の判定は `header-nav.ts`。
