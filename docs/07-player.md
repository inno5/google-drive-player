# 07. ステップ 4: 再生

ステップ 4 のゴールは、ドライブ内一覧とプレイリストの曲をダブルクリックで再生し、現行と同じ操作（再生・停止・前後・シーク・リピート・シャッフル）ができるようにすること。タグの表示と表示モードの切り替えはステップ 5 で扱う。

状態: **実装済み・未検証（2026-09-30）**

## 実装状況

- 実装済み: player feature（`play-queue` / `media-loader` / `audio-element` / `player-store` / `PlayerBar` / `useMediaSession` / `usePlayPauseKey`）、`drive-api.downloadFile`（進捗・401 の再試行）、`shared/lib` の `formatTime` と `click-count`、LibraryPage への接続（両方の一覧からの再生、再生中の行の強調、再生中の曲へスクロール）、対応するテスト。
- 設計との差分:
  - ダブルクリックの判定は `useClickCount.ts` ではなく `shared/lib/click-count.ts`（`createClickCounter`）にした。`TrackRow` と前の曲ボタンで共通に使う。
  - 再生元の一覧を返す `play-sources.ts` は、drive と playlist の store を LibraryPage が渡す関数（`createGetItems`）にした。
  - 曲の Blob は、Drive のメタデータの `mimeType` を種類として付ける（応答の Content-Type が `application/octet-stream` でも再生できるようにするため）。
  - ページタイトルの更新と、サインアウト時の再生停止（`player.stop()`）は `App.vue` に置いた（画面を離れても効くように）。
  - store に `pause()` / `resume()` / `stop()` / `configure()` を加えた（Media Session とテストのため）。
- **未検証**: `check` は未実行。曲順（通常・シャッフル）、Blob の取得と進捗、ダブルクリックの判定、時間の整形は Node で動作を確認した。実際の再生（`<audio>`）と Media Session は未確認。

## 引き継ぐ現行の仕様

| 項目 | 内容 |
| --- | --- |
| 再生の開始 | 行のダブルクリック。最後にダブルクリックした一覧が「再生元」になる |
| 読み込み方式 | `files/{id}?alt=media` を Bearer 付きで fetch し、曲全体を Blob URL にして `<audio>` に渡す。Drive の URL を直接 `<audio src>` にする方式は、過去に使えなくなったため（コミット ccc31de / fe74e0f）。URL にトークンを付ける方式も Drive API では使えない |
| 読み込み中 | シークバーの上にスピナー。次の曲を選んだら、読み込み中のリクエストは中止する |
| 再生モード | 通常 / 1 曲リピート / シャッフル（リピートとシャッフルは排他。押すたびに ON / OFF）。端末に保存する |
| 次の曲 | 通常: 一覧の次（末尾の次は先頭）。1 曲リピート: 曲の終わりでは同じ曲を頭から、「次へ」ボタンでは一覧の次 |
| 一覧が 1 曲だけ | 次・前は同じ曲を頭から |
| シーク | range 入力。時間は `mm:ss`（1 時間以上は `h:mm:ss`） |
| Space キー | 再生・停止を切り替え、「play」「pause」をトーストで出す |
| ページタイトル | 再生中の曲の表示名 |
| 再生中の曲へ | ボタンで、両方の一覧の再生中の行を画面中央までスクロールする |
| ロック画面 | 曲名の表示と、再生・停止・前後・シークの操作（現行でも iOS のロック画面から操作できている） |

## 現行から変えるところ

| 項目 | 現行 | 新しい実装 |
| --- | --- | --- |
| 前の曲ボタン | 押すと前の曲 | **シングルクリックで今の曲の頭へ、ダブルクリックで前の曲**（下の「前の曲ボタン」） |
| 再生エラー | トーストを出して止まる | トーストを出して**次の曲へ進む**。連続 3 曲エラーなら止まる |
| シャッフル | 今の曲以外からランダム（同じ曲が続けて何度も出ることがある） | **一巡するまで同じ曲を出さない**（下の「シャッフル」） |
| ドライブ内一覧からの再生 | 別のフォルダを開くと、次の曲の選び方が不定 | フォルダを開いても再生は止めない。次の曲に切り替わるときは、**開いているフォルダの 1 曲目から**再生する（下の「再生元の一覧」） |
| Blob URL | 解放しない（曲を変えるたびにメモリが増える） | 次の曲を読み込むときに前の URL を `revokeObjectURL` する |
| トークン | 保持中のトークンをそのまま使う（1 時間後に 401 で再生できない） | Drive API と同じく `getValidToken()` を通し、401 なら 1 回だけ取り直して再試行する |
| 今の曲が一覧にない | `findIndex() \|\| 0` の誤りで、次の曲の選び方が不定 | 一覧の 1 曲目から再生する |
| Space キー | 検索欄で Space を押しても再生・停止してしまう | 入力欄・ボタンにフォーカスがあるときは無視する |
| 読み込みの進み具合 | スピナーのみ | シークバーに読み込み済みの割合を表示する（Content-Length から計算） |

## 再生元の一覧（曲順）

- 再生元は `playlist` か `drive`。次・前の曲は、再生元の一覧の「今の並び」（並べ替え後）から選ぶ。フォルダは飛ばし、音声ファイルだけを対象にする。
- **プレイリスト**: 常に最新のプレイリストを使う。再生中の曲を削除しても再生は続け、次の曲は一覧の 1 曲目から選ぶ。
- **ドライブ内一覧**: 常に「今開いている一覧」（フォルダの中身または検索結果）を使う。
    - 別のフォルダや検索に移っても、再生中の曲は止めない。
    - 次の曲に切り替わるとき（曲の終わり・次へ・前へ）、再生中の曲が今の一覧になければ、今の一覧の 1 曲目から再生する（シャッフル中は今の一覧からランダム）。
    - 今の一覧に音声ファイルが 1 曲もなければ、今の曲の終わりで止まる。
- 曲順を決める処理は、Vue に依存しない純粋関数（`play-queue.ts`）にする。

## 前の曲ボタン

- **シングルクリック**: 今の曲の頭へ戻る（押した瞬間に戻す。待たない）。
- **ダブルクリック**（350ms 以内に 2 回）: 前の曲へ。1 回目で頭に戻ったあと、2 回目で前の曲を読み込む。
- 判定の間隔は一覧の行のダブルクリックと同じ（`TrackRow` と同じ仕組みを使う）。
- ロック画面・イヤホンの「前へ」は、ダブル操作ができないので**前の曲**にする（頭に戻すのはロック画面のシークで行える）。

## シャッフル

- 再生元の一覧の曲を、一巡するまで重複なしで選ぶ。一巡したら、今の曲を除いて次の巡目を始める。
- 一巡の途中で一覧に曲が増えたら、その曲も未再生として候補に入る。削除された曲は候補から外れる。
- 再生元が変わったとき（別の一覧でダブルクリック、別のフォルダの曲に移ったとき）は、巡目をやり直す。
- シャッフル中の「前の曲」は、再生した順の履歴を 1 つ戻る。履歴がなければ今の曲の頭へ戻る。
- 乱数は引数で受け取り、テストでは固定する。

## 再生エラー

- 取得の失敗（403・404・ネットワーク）や、`<audio>` が再生できない形式のときは「このファイルは再生できません」をトーストで出し、次の曲へ進む。
- 連続 3 曲エラーになったら止まる（全曲がエラーのときに延々と進まないように）。1 曲でも再生できたら数え直す。
- 一覧が 1 曲だけのときは、進まずに止まる。
- 401（再試行後も）はサインイン画面へ（`AuthExpiredError`）。中止（次の曲を選んだ）は何もしない。

## 構成

```
src/features/player/
├─ play-queue.ts        次・前の曲を選ぶ純粋関数（通常・シャッフルの巡目・履歴）
├─ media-loader.ts      Drive から曲を取得して Blob URL を作る（進捗・中止・前の URL の解放）
├─ audio-element.ts     <audio> を 1 つだけ持つ薄いラッパー（Vue に依存しない。テストで差し替える）
├─ player-store.ts      Pinia: 再生中の曲・状態・時間・モード、play / toggle / next / prev / restart / seek
├─ PlayerBar.vue        シークバー・時間・ボタン（props / emit のみ）
├─ useMediaSession.ts   ロック画面・イヤホンの操作と曲情報
├─ usePlayPauseKey.ts   Space キー
└─ index.ts
src/features/drive/drive-api.ts   downloadFile(id, { signal, onProgress }) を追加（401 の再試行は一覧と共通）
src/features/library/
├─ play-sources.ts      再生元（playlist / drive）の今の曲一覧（音声ファイルだけ）を返す
└─ LibraryPage.vue      PlayerBar を置き、行のダブルクリックを player につなぐ
src/shared/lib/format.ts            formatTime(seconds) を追加
src/shared/lib/useClickCount.ts     シングル / ダブルクリックの判定（TrackRow と前の曲ボタンで共通）
```

- player は drive（`downloadFile` と型）だけを使い、playlist には依存しない。再生元の一覧は LibraryPage が `play-sources.ts` を通して関数で渡す（`getItems(source)`）。
- 「再生中の曲へスクロール」は、LibraryPage が各パネルに合図（連番の props）を送り、パネルが自分の中の再生中の行をスクロールする。

## player store

| 状態 | 内容 |
| --- | --- |
| `current` | 再生中（または読み込み中）の曲。なければ null |
| `source` | `playlist` / `drive` |
| `status` | `idle` / `loading` / `playing` / `paused` / `error` |
| `currentTime` / `duration` | 秒 |
| `loadedRatio` | 読み込み済みの割合（0〜1） |
| `playMode` | `normal` / `repeatOne` / `shuffle`（`gdp:settings` に保存） |

| 操作 | 内容 |
| --- | --- |
| `play(item, source)` | 読み込み中のものを中止し、曲を取得して再生する。再生元が変わったらシャッフルの巡目をやり直す |
| `toggle()` | 再生・停止。曲がなければ何もしない |
| `next()` / `prev()` | 再生元の一覧から次・前の曲を選んで `play` |
| `restart()` | 今の曲の頭へ戻る |
| `seek(seconds)` | 再生位置を変える |
| `setPlayMode(mode)` | 同じモードなら通常に戻す |

- 曲の終わり（`ended`）では、1 曲リピートなら頭から、それ以外は `next()`。
- iOS では、ユーザー操作から時間が空いた `play()` が拒否されることがある。取得の後の `play()` が拒否されたら `paused` にして、再生ボタンで再開できるようにする（エラーとは数えない）。
