# 08. ステップ 5: タグと表示モード

ステップ 5 のゴールは、プレイリストの曲から ID3 などのタグ（アーティスト・曲名・アルバム・トラック番号）を読み取って保存し、表示モードに応じた曲名で表示すること。これで現行の機能がそろう。

状態: **設計確定・実装中**（レビューでの決定は末尾の「決定事項」）

## 範囲

| 含む | 含まない |
| --- | --- |
| タグの読み取り（プレイリストの曲）と、端末への保存 | ドライブ内一覧の行へのタグ表示（ファイル名のまま。検索などで大量のタグ読み取りを避けるため） |
| 表示モード（タイトル - アーティスト / 詳細 / ファイル名）と切り替えボタン | ジャケット画像・歌詞の表示 |
| 対象の形式は mp3（ID3 タグ）のみ | m4a・flac などのタグ |
| プレイリストの行・ページタイトル・ロック画面の曲名への反映 | タグの編集 |
| ドライブ内一覧から再生した曲のタグの読み取り（プレイリストにない曲はファイル名のまま） | |

## 引き継ぐ現行の仕様

| 項目 | 内容 |
| --- | --- |
| 読み取るタグ | アーティスト・曲名・アルバム・トラック番号 |
| 対象 | プレイリストの曲（フォルダは除く） |
| 読み取りの方法 | `files/{id}?alt=media` に Bearer を付け、jsmediatags が Range リクエストで必要な部分だけを取得する。読み取りは同時に最大 10 件（決定） |
| 読み取るタイミング | プレイリストに追加したとき、アプリを開いたとき |
| キャッシュ | 曲ごとに `[更新日時, アーティスト, 曲名, アルバム, トラック]` を保存する。Drive 上の更新日時が変わった曲だけ読み直す |
| 表示モード | 「タイトル - アーティスト」→「アーティスト / アルバム [トラック] - タイトル」→「ファイル名」→ 最初に戻る。切り替えボタンは再生中の曲へのボタンの左。切り替えるとモードの内容をトーストで出す。端末に保存する |
| 表示先 | プレイリストの行、ページタイトル。ドライブ内一覧の行はファイル名のまま |
| タグがない曲 | ファイル名で表示する |

## 現行から変えるところ

| 項目 | 現行 | 新しい実装 |
| --- | --- | --- |
| キャッシュの保存 | 曲ごとに `meta-{id}` のキーを作る（曲数だけキーが増え、消されない） | 1 つのキー `gdp:tags`（`{ version: 1, tags: { [id]: … } }`）にまとめる。書き込みは 500ms まとめて行い、プレイリストにない曲（と再生中の曲）の分は保存時に捨てる |
| タグの読み取りに失敗した曲 | 何も保存せず、アプリを開くたびに読み直す | 「タグがない」ファイルは、タグなしとして保存して読み直さない。通信・認証のエラーは保存せず、次にアプリを開いたとき読み直す（同じ起動中は再試行しない） |
| トークン | 保持中のトークンをそのまま使う | 読み取りのたびに `getValidToken()` を通す |
| 表示名の規則 | アーティストと曲名の両方がないとファイル名になる（詳細モードでも） | 変えない（決定）。下の「表示名の規則」 |
| 表示の更新 | タグを読むたびにプレイリストの配列を `splice(0, 0)` で強制的に再描画する | タグの store を読むだけで、画面が自動で更新される |
| ロック画面 | 曲名だけ | タグが揃っている曲は、曲名・アーティスト・アルバムを分けて出す（ファイル名モードでは曲名にファイル名だけ） |
| ページタイトル | 再生を始めた時点の表示名 | 表示モードを変えたり、タグを読み終えたりしたら追従する |
| 文字化け | 補正なし | Shift_JIS のバイト列が ISO-8859-1 として保存されたタグを補正する（下の「文字化けの補正」） |
| タグ読み取りの依存 | `jsmediatags` の個人フォークを、型なしで直接 import | 1 つのファイルの中だけに閉じ込め、型を付ける（下の「構成」） |

## 表示名の規則

現行と同じ。タグの各項目は、空文字なら「ない」ものとして扱う。**アーティストと曲名のどちらかがなければ、どのモードでもファイル名を表示する。**

| モード | 規則 | 例 |
| --- | --- | --- |
| タイトル - アーティスト（既定） | `曲名 - アーティスト` | `Song - Artist` |
| 詳細 | `アーティスト / アルバム [トラック] - 曲名`。アルバム・トラックがなければ、その部分を省く | `Artist / Album [3] - Song` |
| ファイル名 | ファイル名 | `03 song.mp3` |

- 詳細モードの組み立ては、`アーティスト`、`アルバム`、`[トラック]`（アルバムの直後。アルバムがなければアーティストの直後）を順に並べ、アーティストとアルバムの間に ` / `、それらと曲名の間に ` - ` を入れる。
- トラックは、タグの値をそのまま出す（`3/12` ならそのまま `[3/12]`）。
- ドライブ内一覧から再生した曲で、プレイリストにない曲はタグを読まないので、ファイル名で表示する。
- 切り替えたときのトーストと、ボタンのアイコン（`list`）は、現行版と同じにする。文言は英語（`title - artist` / `artist / album [track] - title` / `file name`）。

## 文字化けの補正

日本語（や中国語）のタグ付けソフトの中には、ID3v2 の文字コードの指定を ISO-8859-1 にしたまま、中身を Shift_JIS（CP932）のバイト列で書くものがある（例: `96 EE 88 E4 93 63 81 40 93 B5` → 「矢井田　瞳」）。ID3v1 も同様に Shift_JIS のことがある。jsmediatags はこれを ISO-8859-1 として読むため、文字化けする。

`tag-reader.ts` の中で、読み取ったアーティスト・曲名・アルバムに `fixLatin1Mojibake(text)` をかける。

1. 全文字が U+0000〜U+00FF で、U+0080 以上を 1 文字以上含む場合だけ対象にする（正しい UTF-8・UTF-16 として読めたタグ、ASCII だけのタグには何もしない）。
2. 各文字をバイトに戻し、`TextDecoder` に `fatal: true` で、`shift_jis`、`gbk` の順に試す。最初に読めたものを採る。どちらも失敗したら元の文字列のまま返す。GBK は、中国語圏のソフトが日本のアーティスト名を GBK で付けている mp3（2 つ目のサンプル。RIFF（RMP3）に包まれ、ID3v1 だけが付いていた）に対応するため。
3. デコード結果が半角カナ（U+FF61〜U+FF9F）だけで（その文字コードでは採らず、次を試す）、それ以外の非 ASCII を含まない場合は、Latin-1 の文字（`¡` など）を誤って変換した可能性が高いので、元の文字列のまま返す。

`Café` のように末尾が不完全なバイト列は、ステップ 2 の失敗で元のまま残る。Latin-1 の文字が隣り合う場合（`éà` など）は誤って変換される可能性があるが、日本語の楽曲での実用を優先する。

## 読み取りとキャッシュ

```
プレイリストが変わる ─▶ tag store の sync(items)
                          ├─ 保存済みで、更新日時が同じ曲 → 何もしない
                          └─ それ以外 → キューに積む（同じ曲は 1 度だけ）
キュー ─▶ 最大 10 件を同時に tag-reader で読む ─▶ 結果を保存（500ms まとめて）
```

| 読み取りの結果 | 動き |
| --- | --- |
| タグが読めた | 保存して表示に反映する |
| タグがないファイル（形式は読めたが、タグがない・対応しない形式） | 空のタグとして保存する。同じ更新日時のうちは読み直さない |
| 通信・認証のエラー、中止 | 保存しない。その起動中は再試行しない（次にアプリを開いたとき読み直す） |
| 読み取り中にプレイリストから消された曲 | 結果を捨てる |
| サインアウト | キューを空にして読み取りを止める（保存済みのタグは残す） |

- 更新日時が変わった曲（Drive 上でファイルが更新された）は、プレイリストへの再追加で情報が更新されたとき読み直す。
- タグの保存は、`shared/storage` を通す。保存に失敗しても、メモリ上のタグは使い続ける（トーストは出さない）。

## 構成

```
src/features/tags/
├─ tag-types.ts          TrackTags 型（更新日時・アーティスト・曲名・アルバム・トラック）
├─ tag-reader.ts         タグの読み取り（jsmediatags をここだけで使う）と文字化けの補正。結果は ok / none / failed
├─ jsmediatags.d.ts      jsmediatags の使う部分だけの型
├─ tag-storage.ts        gdp:tags の読み書きと形式の検証
├─ display-name.ts       表示名の組み立てと、モードの切り替え順（純粋関数）
├─ tag-store.ts          Pinia: tags、displayMode、sync / displayName / mediaMetadata / cycleDisplayMode / clearQueue
└─ index.ts
```

- tags は playlist・drive を import しない。曲の情報（`{ id, name, mimeType, modifiedTime }`）だけを受け取る。
- tag-store は、読み取りの実体（`tag-reader`）を差し替えられるようにする（テストではモックを使う）。
- 表示モードは `gdp:settings.displayMode`（`titleArtist` / `full` / `fileName`）に保存する（`patchSettings`）。
- 配線（LibraryPage）:
    - `watch(playlist.items)` で `tags.sync(items)` を呼ぶ。
    - PlaylistPanel に `displayName`（関数）を渡す。
    - PlayerBar に表示モードのボタンを追加する（PlayerBar は tags を知らず、ラベルの文字列を受け取って `cycleDisplayMode` を emit するだけ）。ロック画面の曲情報は `tags.mediaMetadata`、ページタイトルは `tags.displayName` から作る。
- ページタイトルの更新は、表示名を使うため `App.vue` から LibraryPage 側へ移す（app 層が features の内部の状態に依存しすぎないようにするため）。LibraryPage を離れるときにタイトルを既定に戻す。サインアウトでは `tags.clearQueue()` を呼んで読み取りを止める（App.vue）。

## 依存ライブラリ

- 現行の `jsmediatags` の個人フォーク（`inno5/jsmediatags#feature/addCustomHttpHeader`。Authorization ヘッダーを付けられるようにしたもの）を継続する。`package.json` には GitHub の依存として書く。
- 上流の `jsmediatags` には、リクエストヘッダーを付ける公式の手段がない。代替案（上流版＋自作のリーダー、自作パーサー）は採用しなかった（決定事項 1）。

## 決定事項

| # | 論点 | 決定 |
| --- | --- | --- |
| 1 | タグ読み取りのライブラリ | (A) 現行の個人フォークを継続する。手持ちの音源は mp3 のみ。タグが読めない曲は、現行どおりファイル名で表示する |
| 2 | キャッシュの保存先 | 1 つのキー `gdp:tags` にまとめる（プレイリストは多くても 100 曲程度） |
| 3 | 表示名の規則 | 現行と同じ（アーティストか曲名のどちらかがなければファイル名） |
| 4 | ドライブ内一覧から再生した曲のタグ | 読まない（プレイリストの曲だけ読む） |
| 5 | 読み取りの並行数と失敗時の扱い | 同時 10 件。「タグなし」の結果はキャッシュする。通信・認証のエラーはキャッシュせず、同じ起動中は再試行しない |
| 6 | ドライブ内一覧の行 | ファイル名のまま（検索中に大量のタグを読まないため） |
| 7 | 文字化けの補正 | 上の「文字化けの補正」の方針で実装する（サンプルの mp3 で原因を確認済み） |
