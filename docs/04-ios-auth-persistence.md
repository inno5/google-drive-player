# 04. iOS「ホーム画面に追加」時の認証永続化

## 症状

iOS でホーム画面に追加して起動した場合、アプリを終了（タスクキル）するたびに localStorage 上の保存データと Google のログイン情報が消え、再サインインが必要になる。

## 方針（2026-09-30 決定）

- 認証ライブラリは現行の gapi.auth2（Google Sign-In JavaScript platform library）を継続して使う。現行のクライアント ID で動作することは実機で確認済み。
- まず、アプリ自身が保存データを消している処理（下記の原因）をなくす。
- そのうえで、ホーム画面アプリでログイン状態がどこまで保たれるかを実機で確かめる。足りなければ、下の「追加の対策」を順に試す。

## 決定事項

- 2026-09-30: ホスティングは Firebase Hosting のみとし、サーバー側の処理（Cloud Functions、Supabase など）は持たない。
- 2026-09-30: iOS でのログイン維持は、保存済みトークンの再利用（A2）で行う。トークンの有効期間（約 1 時間）を過ぎたら、ログイン画面から入り直す。
- 実機確認済み: v1.2.7 の全消去の廃止と、A2 の追加で、iOS で終了して開き直してもログイン状態が保たれる。

### 採用しなかった案（リフレッシュトークンによる自動更新）

操作なしで 1 時間を超えてもログインを保つには、サーバーがリフレッシュトークンを保管し、アクセストークンを再発行する構成が必要になる。次の理由で見送った。

| 候補 | 見送った理由 |
| --- | --- |
| Firebase Cloud Functions | Spark（無料）プランでは使えず、従量課金の Blaze プラン（カード登録）が必要 |
| Supabase（認証 + Edge Functions） | 無料プロジェクトは 1 週間まったく使われないと自動停止する。数日に一度しか開かない使い方では停止に当たる可能性がある |

条件が変わったとき（カード登録を許容する、常時使う用途になる など）は、この構成を再検討する。方針は「認可コードを `grantOfflineAccess()` で取得 → サーバーがリフレッシュトークンを保管 → `/api/token` でアクセストークンを返す」。

## 原因（アプリ自身による全消去）

現行の `src/services/auth-service.ts` の `_updateSigninStatus()` は、`isSignedIn` が false だと `appState.clearLocalStorage()`（= `localStorage.clear()`）を実行する。このメソッドは起動時（`init()` 内）と、`isSignedIn.listen` のたびに呼ばれる。

そのため、起動時に gapi.auth2 が一瞬でも「未サインイン」と返すと、その時点で保存データがすべて消える。消える対象はプレイリスト、設定、タグのキャッシュ、そして localStorage 上にある認証関連の値すべて。

対策（新しい実装で [03](./03-step1-foundation.md) のとおりに行う）:

- 「未サインイン」と判定されただけでは何も消さない。
- 消すのはユーザーが明示的にサインアウトしたときだけにし、対象も認証関連のキーに限る。
- 初期化中（`unknown`）と未サインイン（`signedOut`）を区別する。

## 現行版（Vue 2）での先行検証

ブランチ `fix/keep-storage-on-signin-check` で、現行版に次の修正を入れて検証する。

- `auth-service.ts`: 未サインインと判定されても `localStorage.clear()` しない。`currentUser.listen` を追加し、アクセストークンの自動更新を反映する。
- `utils/debug-log.ts`（新規）: 起動ごとの記録を直近 10 回分、`ls-key-debug-boot-log` に残す。記録するのは、起動時刻、ホーム画面起動かどうか、起動時の localStorage のキー数とプレイリストの曲数、認証初期化の直後と 5 秒後の `isSignedIn`。
- ヘッダーの設定アイコン（旧「?」）のボタンで、起動ログのあるデバッグ画面を開く。
- `auth-service.ts`（A2）: `gapi.auth2` が未サインインと判定しても、直近に取得したアクセストークン（`ls-key-auth-token`）の残り有効期間が 5 分以上あれば、そのトークンでサインイン状態にする。`gapi.client.setToken()` にも渡す。ログには `token:○` と出る。保存したトークンを消すのは、ユーザーが明示的にサインアウトしたときだけ。
  - トークンの有効期間（約 1 時間）を過ぎたら、通常どおりサインイン画面から入り直す。

ログの読み方の例: `[HOME] keys:6 list:25 auth:×→○`

| 項目 | 意味 |
| --- | --- |
| `[HOME]` | ホーム画面アプリとして起動した（`[WEB]` はブラウザで開いた） |
| `keys:6 list:25` | 起動した時点で保存データが残っていた |
| `auth:×→○` | 初期化の直後は未サインインで、5 秒後にはサインイン済みになった |

- `list` が再起動のたびに 0 に戻る → 全消去以外にも原因がある。
- `auth` が `×→×` のままになる → gapi.auth2 がセッションを復元できていない。「追加の対策」へ進む。

## 前提（公式情報）

- ホーム画面の Web アプリは Safari の一部ではなく、ストレージと利用日数カウンタを Safari とは別に持つ。
- 7 日間無操作で script から書き込んだストレージを消す ITP の制限は、ホーム画面アプリのファーストパーティには適用されない。したがって、全消去をやめれば保存データ自体は残るはず。
- ITP はサードパーティ Cookie を例外なくブロックする。gapi.auth2 が `accounts.google.com` の iframe でセッションを確認する部分は、ホーム画面アプリでは期待どおりに動かない可能性がある（これが「起動時に未サインイン判定 → 全消去」の引き金になっていると推測される）。
- gapi.auth2 は 2022-07-29 以降に作られたクライアント ID では使えない。現行 ID を維持すること。停止日は未定。

出典: [WebKit: Full Third-Party Cookie Blocking and More](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/) / [WebKit Tracking Prevention](https://webkit.org/tracking-prevention/) / [Google Sign-In: Deprecation and Sunset](https://developers.google.com/identity/sign-in/web/deprecation-and-sunset)

## 実験

プレビューチャンネルの URL をホーム画面に追加して試す。1 つの実験ごとに、アプリを「タスクキル → 再起動」する操作を 3 回以上繰り返す。

| # | 実験 | 見るもの |
| --- | --- | --- |
| E0 | 計測ページ `/debug` を用意する。localStorage・sessionStorage・IndexedDB・Cookie のキー一覧、`navigator.standalone`、起動時の `isSignedIn` の値の推移、起動時刻の履歴を表示する | 以降の実験の記録係。gapi.auth2 がどこに何を保存しているかを把握する |
| E1 | 全消去をなくした実装で、終了と再起動を繰り返す | 保存データが残るか。gapi.auth2 が起動後に `isSignedIn = true` を返すか |
| E2 | サインインから 1 時間以上たってから再起動する | トークン更新（`reloadAuthResponse`）が効き、Drive API が 401 にならないか |
| E3 | ポップアップ方式のサインインをホーム画面アプリ内で行う | ポップアップが開いてアプリに戻ってくるか |

## 追加の対策（E1〜E3 で不足があった場合、上から順に試す）

| # | 対策 | 内容 |
| --- | --- | --- |
| A1 | 起動時の判定を待つ | `isSignedIn` が最初に false でも、`listen` で true に変わるまで数秒待ってから `signedOut` を確定する |
| A2（実装済み） | トークンを自前で保持する | 最後に得たアクセストークンと `expires_at` をアプリのキーで保存する。起動時に期限内なら `gapi.client.setToken()` で即座に使い、gapi.auth2 の復元を待たずに再生できるようにする |
| A3 | リダイレクト方式 | `ux_mode: 'redirect'` でサインインし、アプリの外にあるポップアップを使わない |
| A4 | 永続ストレージを要求する | `navigator.storage.persist()` を呼ぶ |

A2 はトークンの寿命（約 1 時間）の範囲でしか効かない。それを超えてもログイン状態を保つには、gapi.auth2 による復元が働くことが前提になる。
